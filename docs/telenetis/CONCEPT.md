# Telenetis — концепція продукту

**Telenetis** — Rust-сервер (`S:/rust/GSV/telenetis`, порт **9800**), що робить
Telegram-телефони повноцінними учасниками GSV-екосистеми: Mini App для людини
і edge-воркер для мережі. Один бінар — два обличчя: аплікація в Telegram
і міст між телефоном, хабом, координатором і інференсом.

## Навіщо

Телефони вже в кишені і вже в Telegram. Замість Termux, нових протоколів і
окремих застосунків Telenetis використовує те, що є: Mini App як UI,
WebGPU телефону як обчислення, Download-папку як накопичувач, а черги
poolAI і шину GSV як control plane.

## Карта

```
телефон → Telenetis :9800 → Hub :9999 / PoolAI :8091 / llama :8080
                 ↑
        тільки сюди ходять телефони — напряму в Hub/PoolAI/llama ніколи
```

| Сутність | Роль |
|---|---|
| Bot | Команди, кнопки, webhook/long-polling (`src/bot/`) |
| Mini App | WebView-сторінки: дошка, потоки, ролі, probe, tensor (`src/ui/`) |
| Hub (GSV :9999) | Тікети, шина, grid-профілі, keep-live |
| PoolAI (:8091) | Черги задач, біндинги, VM |
| llama | Інференс: серверний `:8080` + телефонний wllama-воркер |

## Принципи (не обговорюються без власника)

1. **Телефон говорить тільки з Telenetis.** Зовнішні сервіси — через allowlist reverse proxy (`/edge/upstream/{llama,poolai}`).
2. **Мутації — тільки з перевіреним `initData`.** HMAC-SHA256, `auth_date` ≤24h, `user` обов'язковий. Читання — відкриті.
3. **Сервер не вгадує.** Невідоме RAM/VRAM = 0, невідомий пір = чиста помилка (fail-open, ніколи 500 без форми).
4. **IDB — кеш, Download — накопичувач.** Кеш виселяється, файл у Download лишається. Вибір моделі липне, байти — ні.
5. **Фону нема.** Згорнутий Telegram = заморожений WebView; працюють сервер, черги і бот-push. Архітектура це враховує, а не бореться.
6. **Без згоди хост не тестить.** Галочка в аплікації → реєстр → тільки allowlist-задачі (`test_ping`); вимкнення = видалення запису.
7. **Підказки, не автодії.** Сервер радить наступний крок (claim/next), але ніколи не клеймить сам. Ownership — за власником.

## Поверхні

| Шлях | Що |
|---|---|
| `/app /board /flows /roles` | Mini App: дошка тікетів, потоки, ролі |
| `/api/snapshot` | Все одним запитом + `next_hint` |
| `/api/board/*` | claim/done/error/reclaim → форвард у Hub |
| `/probe` + `/api/edge/webgpu` | WebGPU-профіль телефона → Hub (`class=webgpu`) |
| `/tensor` | Браузерний воркер: GGUF у телефоні, задачі `llama_chat` з черги, чейн з 6 ходів |
| `/torrents/*.torrent` + `/models/*` | Роздача байтів (webseed; `attachment` для сейву) |
| `/tracker` + `/api/edge/tracker/status` | WS-сигналінг phone-to-phone; статус роїв без ідентифікаторів |
| `/api/testmode`, `/api/edge/testmode/peers` | Згода на тести; список для харнеса |
| `/ws`, `/events` | Живі потоки (WS primary, SSE fallback) |

## Гарантії та не-цілі

Гарантуємо: initData-перевірку скрізь де мутація; чисті помилки замість 500;
докачку Range; персист вибору моделі; чесні статуси (кеш/рій/згода видно);
жодного шарінгу ваг і активацій між телефонами — кожен тримає цілу модель
(причина: prompt inversion по проміжних активаціях дає 88.4% точності токенів,
PIA arXiv 2503.09022; pipeline як у Petals — тільки для CUDA-серверів,
wllama вміє лише цілі GGUF локально).
Не обіцяємо: фонову роботу; вічний кеш; one-tap Save з cross-origin (HF);
`answerWebAppQuery` без keyboard-flow; нові протоколи розподілу тензорів;
"SwarmLLM" як іменованої методології не існує — фіксовані
82ms/15ms/3-5 вузлів і `next_hint` для буферів відхилено як безджерельні.

## Стан і ворота

Код покрито емулятором (`src/emu.rs`, `tests/phone_emulator.rs`,
`tests/phone_tour.rs`) — ворота перед телефонами. Телефонам лишається тільки:
тапи, Download Manager, справжній WebGPU, P2P-байти. Ранбук:
[`TWO_PHONES.md`](TWO_PHONES.md). Живий `:9800` оновлюється тільки респауном
у вікні власника. Owner-gated: rotate token, group ownership.
